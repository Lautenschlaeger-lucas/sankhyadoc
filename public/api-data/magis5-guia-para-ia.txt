## Integração de Produtos
  #### Cadastrar um produto no Magis5
  -	O ideal no momento de criar um produto no magis5 é que isso seja on-time, ou seja, sempre que for cadastrado um produto NOVO no ERP, também realizar este cadastro no Magis5.
  -	Para criar um produto no magis5 será utilizado o endpoint [/v1/products](#api/api-docs?view=reference&item=post-products)
  -	Se tratando de uma integração com um ERP não é necessário preencher todos os campos, mas sim os campos que o ERP possui ou tem controle gerencial, como por exemplo: Código/Sku, Título, Marca, Modelo, EAN, EAN Tributável, NCM, Origem, Cest, Condição do produto, Localização, Dimensões (Altura, Largura, Comprimento, Peso), Descrição.
   -	O único campo obrigatório para criação de um produto é o Código/Sku, preenchido no campo "id".

  -	Abaixo segue um exemplo de payload dos dados:

-	Para atualizar um produto no Magis5 é indicado a utilização do método PATCH **(para que dados preenchidos posteriormente não sejam apagados)**.

### Buscando os pedidos para serem criados no ERP
  -	Os pedidos que devem ser criados no ERP devem ser somente os pedidos que estiverem no status de **“Ag. Separação”** _(ready_to_print)_, somente este status garante um pedido completo e já com todos os dados necessários para ser processado no ERP.
  -	[**Busca para buscar a lista de pedidos a serem criados no ERP**](https://app.magis5.com.br/v1/orders?status=ready_to_print&queueStatus=blank)  
  -	O parâmetro _**queueStatus**_ irá garantir que o mesmo pedido não se repita ao realizar a consulta acima novamente, mas para isso será necessário atualizar o campo _**queueStatus**_ assim que o pedido for criado no ERP.
  -	Para isso, será necessário realizar um PATCH com os seguintes dados:
    - https://app.magis5.com.br/v1/orders/{order.id} 
    - Body:
    ```json
      {
          "queueStatus" : "INTEGRADO"
      }
    ```
    - O valor _“INTEGRADO”_ pode ser substituído por qualquer outra informação, o campo _**queueStatus**_ é livre e pode ser colocado qualquer informação.
    -	Como a consulta constante aos pedidos _**ready_to_print**_ será passado por parâmetro o _**queueStatus=blank**_, isso faz com que os pedidos não se repitam mais neste processo de criação de pedido.

### Enviando os dados de faturamento
-	Após subir o pedido para o ERP e atualizar o _**queueStatus**_, seguimos para a próxima etapa que é o faturamento, emissão de nota fiscal e envio do XML para o pedido no Magis5.
-	Para isso, será necessário realizar um POST com os seguintes dados:
  - Caso utilize a expedição de seu ERP/WMS: [**{{url}}/v1/invoices/{completeOrderNumber}?releaseOrder=true**](#api/api-docs?view=reference&item=post-invoices-completeordernumber) 
  - Caso utilize a expedição do Magis5: [**{{url}}/v1/invoices/{completeOrderNumber}?releaseOrder=false**](#api/api-docs?view=reference&item=post-invoices-completeordernumber)
  - O parâmetro "releaseOrder" irá definir o comportamento do pedido ao receber o XML da NF-e: 
  - Com valor **true**, o pedido avançará para Faturado (billed), e terá essa NF-e enviada ao canal de venda, simulando a expedição realizada no painel Magis5, para que a etiqueta de envio possa ser coletada via [GET orders/{completeOrderNumber}](#api/api-docs?view=reference&item=get-orders-completeordernumber), na estrutura tags[] do pedido;
  - Com valor **false**, o pedido permanecerá em Ag. Separação (ready_to_print), para que seja exibido em nosso módulo de Expedição e possa ser expedido efetivamente pelo painel do HUB Magis5.
  - Body:
  ```json
    <?xml version="1.0" encoding="UTF-8"?><nfeProc ……..</xml>
    (XML COMPLETO DA NOTA FISCAL)
  ```
    - **Só será aceito XMLs que tenham a tag <?xml e nfeProc**
    - Geralmente uma nota fiscal que não tem nfeProc significa que a nota fiscal ainda não foi emitida 100%.

===== Rate Limiting =====
# Limites de Requisição (Rate Limiting)

Para garantir a estabilidade, segurança e um excelente desempenho da nossa API para todos os clientes, aplicamos limites de taxa (Rate Limits) nas chamadas aos nossos endpoints.

Limite Máximo: 600 requisições por minuto.

Como é medido: O limite é contabilizado com base na sua chave de API (header X-MAGIS5-APIKEY) e no seu endereço IP.

Comportamento ao exceder: Caso a sua aplicação ultrapasse esse limite de 600 chamadas dentro de uma janela de 60 segundos, a API passará a rejeitar temporariamente as novas requisições, retornando o código de status HTTP 429 Too Many Requests.

Recomendação de Boas Práticas:
Recomendamos que a sua integração seja desenhada para lidar com o código 429 de forma elegante. Ao receber este status, sua aplicação deve pausar as requisições e utilizar uma estratégia de retentativa com atraso progressivo (Exponential Backoff) antes de tentar novamente.
