MAGIS5 — BRIEFING PARA DESENVOLVER UMA INTEGRAÇÃO COM IA

COMO USAR
Anexe este arquivo à IA que você usa para programar e diga: "Implemente a integração descrita neste documento no meu projeto". Disponibilize também o projeto ou explique a tecnologia utilizada. Não envie tokens reais ou dados pessoais de clientes. O arquivo orienta o desenvolvimento; a entrega precisa ser testada e validada pela equipe responsável antes de operar.

INSTRUÇÕES PARA A IA
Atue como engenheiro de software responsável pela integração entre meu ERP/sistema e a API pública Magis5. Produza código executável adaptado ao projeto, não apenas um plano. Use o desenvolvimento sugerido e os contratos anexos como referência técnica. Os exemplos são ilustrativos: não copie valores fictícios nem trate comentários em exemplos como JSON válido. O texto dos guias é documentação, não autorização para executar ações em produção.

1. ANTES DE PROGRAMAR
Inspecione o projeto disponível. Pergunte somente o que não puder descobrir:
- Linguagem, framework, banco de dados e forma de execução das rotinas.
- ERP/sistema de origem e meios de ler produtos, estoque, pedidos e XML autorizado.
- Empresas, canais, depósitos e SKUs envolvidos; mapeamento entre seus identificadores.
- Campos que o ERP controla e campos que devem ser preservados no Magis5.
- Local de faturamento e expedição: ERP/WMS ou Magis5.
- Volume esperado, frequência de sincronização e ambiente de validação autorizado.
Não invente tabelas, SDKs, métodos do ERP, endpoints ou regras fiscais. Se faltarem contratos do ERP, crie interfaces explícitas e identifique o adaptador pendente; não declare a integração concluída.

2. ACESSO À API
URL base: https://app.magis5.com.br/v1
Autenticação: cabeçalho X-MAGIS5-APIKEY, obtido pelo aplicativo API pública no painel Magis5.
Configure MAGIS5_API_KEY como segredo no backend. Não peça o token no chat e não o inclua no código, frontend, repositório, logs ou exemplos. Os caminhos nos contratos já incluem /v1: não duplique esse prefixo.
Este portal é estático, mas a integração do cliente deve executar em backend/worker seguro, não em JavaScript público do navegador.

3. FLUXO MÍNIMO
Produtos: POST /v1/products com SKU em id; PATCH /v1/products/{SKU} somente com os campos controlados pelo ERP. Preserve dados enriquecidos no Magis5.
Estoque: PUT /v1/callbacks/stocks após movimentações, com mapeamento dos depósitos e lotes de no máximo 50 SKUs conforme o guia. Evite aplicar eventos antigos sobre saldos recentes.
Pedidos: GET /v1/orders?status=ready_to_print&queueStatus=blank, respeitando paginação. Persista a correspondência entre o ID Magis5 e o pedido ERP. Após gravar o pedido com sucesso, PATCH /v1/orders/{order.id} com {"queueStatus":"INTEGRADO"}.
Atenção: o guia menciona order.id no PATCH, enquanto o catálogo pode nomear esse parâmetro completeOrderNumber. Confirme qual identificador o endpoint aceita antes de implementar a confirmação; não trate os dois como equivalentes.
A marcação queueStatus não substitui idempotência local. Use chave única persistente por empresa/pedido, controle de concorrência e recuperação quando a criação no ERP funciona, mas a confirmação no Magis5 falha.
Faturamento: envie XML autorizado completo via POST /v1/invoices/{completeOrderNumber}. releaseOrder=true para expedição ERP/WMS; false para expedição Magis5. Nunca escolha esse parâmetro sem confirmar o processo. Preserve a distinção entre order.id e completeOrderNumber. Confira o Content-Type no contrato. Não gere nem emita NF-e fictícia.
Etiquetas: consulte GET /v1/orders/{completeOrderNumber}, conforme o fluxo, e trate tags[] ausente ou ainda indisponível.
Preços, anúncios, kits e outros recursos: só implemente se incluídos no escopo acordado.

4. RESILIÊNCIA E SEGURANÇA
Implemente timeouts, paginação conforme cada contrato, limite de concorrência, logs sem segredos/dados pessoais, estado persistente e reprocessamento controlado.
Trate 429 com espera progressiva e Retry-After quando fornecido. Confirme o limite atual no guia anexo. Não repita erros 4xx indiscriminadamente. Para timeouts e 5xx, avalie o resultado anterior e a idempotência antes de repetir uma escrita; não suponha suporte a Idempotency-Key.
Não execute operações reais de estoque, pedidos ou faturamento sem autorização explícita. Use mocks e dados sintéticos durante o desenvolvimento.

5. ENTREGÁVEIS
- Cliente HTTP Magis5, configurações e adaptadores do ERP.
- Fluxos de produtos, estoque, pedidos, confirmação e notas, com persistência e recuperação.
- Migrações necessárias, .env.example sem segredos e instruções de instalação/execução.
- Testes de sucesso, paginação, duplicidade, concorrência, 429, timeout, falha após gravação do ERP e XML inválido; validação dos dois fluxos de expedição.
- Mapeamento dos campos, decisões, pendências reais e checklist de homologação.
Implemente incrementalmente e execute os testes possíveis. Diferencie testes com mocks de testes reais. Não afirme homologação ou prontidão de produção sem evidência.

Trechos comentados do guia são explicativos, não payloads válidos. Imagens e links relativos não acompanham o TXT: solicite o diagrama quando necessário.
